# gee/ (เวอร์ชัน polygon)

## 1. ภาพรวม

เราอยากรู้ว่าแต่ละชุมชน "ร้อนแค่ไหน" "เขียวแค่ไหน" และ "แน่นด้วยอาคารแค่ไหน" แล้วเอาไปเทียบกัน
ขั้นตอนมี 4 ขั้น

1. กำหนดขอบเขตของแต่ละชุมชนเป็น **polygon**
2. ขยายขอบเขตออกไปอีก 2 ระยะ (300 ม. และ 500 ม.) ให้ครอบคลุมพื้นที่โดยรอบ
3. ในแต่ละขอบเขตที่ขยายแล้ว สรุปข้อมูลจากภาพดาวเทียมและแผนที่อาคารเป็นตัวเลข
4. ได้ตาราง CSV 3 ไฟล์ (ความร้อน, พื้นที่สีเขียว, อาคาร) ส่งต่อเข้า pipeline

```
polygon ชุมชน → ขยาย 300 / 500 ม. → สรุปค่าจากดาวเทียม/แผนที่อาคาร → CSV 3 ไฟล์ → pipeline
```

## 2. เราคำนวณเรื่อง polygon อย่างไร

### 2.1 polygon ของชุมชน
- เรายังไม่มีขอบเขตชุมชนจริง จึงสร้าง **วงกลมรัศมี 150 เมตร** รอบจุดศูนย์กลางของแต่ละชุมชน (36 ชุมชน) พื้นที่วงกลมละประมาณ 70,700 ตร.ม.
- จุดศูนย์กลางมาจากรายชื่อชุมชนหลัก (`communities.csv`) รหัสชุมชนใช้ตามไฟล์นั้นทุกประการ
- ถ้าวันหลังได้ polygon ขอบเขตจริง ใช้แทนวงกลมได้เลย โดยไม่ต้องเปลี่ยนวิธีคำนวณ

### 2.2 การขยายพื้นที่ (buffer)
buffer คือการ **ขยาย polygon ออกจากขอบ** ตามระยะที่กำหนด ไม่ใช่การวัดรัศมีจากจุดศูนย์กลาง

| buffer_m | ระยะขยายจากขอบ | รัศมีรวมจากจุดศูนย์กลาง | พื้นที่โซนโดยประมาณ |
|---|---|---|---|
| 300 | +300 ม. | 150 + 300 = **450 ม.** | ~636,000 ตร.ม. |
| 500 | +500 ม. | 150 + 500 = **650 ม.** | ~1,327,000 ตร.ม. |

- ค่า `buffer_m` ใน CSV คือระยะที่ขยายจากขอบ ไม่ใช่รัศมีรวม ถ้าเขียนใน report ต้องบอกให้ชัด
- ผลที่ตามมา: **ตัวเลขจะไม่เท่ากับเวอร์ชันจุดเดิม** ซึ่งใช้วงกลมรัศมี 300/500 ม. รอบจุดพอดี ห้ามเอาสองเวอร์ชันมาเทียบกันตรงๆ
- โซนของชุมชนที่อยู่ใกล้กันจะ **ซ้อนทับกัน** ได้ แต่ละชุมชนคำนวณแยกกัน ไม่ได้แบ่งพื้นที่ให้กัน

### 2.3 หน่วยการคำนวณ
ทุกแถวใน CSV = **1 ชุมชน × 1 buffer × 1 ปี** ตอนนี้ใช้ปีเดียว (2026) จึงได้ 36 × 2 × 1 = **72 แถวต่อไฟล์**

## 3. สรุปข้อมูลจากอะไร และคำนวณอย่างไร

ทุกค่าคำนวณ "ภายในโซน" (polygon ที่ขยายแล้ว) ของแต่ละชุมชน

### 3.1 ความร้อน (LST) — ไฟล์ `lst_2026.csv`
- **ที่มาของข้อมูล:** ภาพดาวเทียม Landsat 8 และ 9 (ช่องวัดอุณหภูมิพื้นผิว) ช่วง มี.ค.–พ.ค. 2026 ซึ่งเป็นช่วงร้อนที่สุดของปี
- **ขั้นตอน:** ตัดพิกเซลที่ถูกเมฆ เงาเมฆ หรือ cirrus บัง → แปลงค่าเป็นองศาเซลเซียส → รวมภาพทั้งฤดูเป็นภาพเดียวโดยใช้ค่ามัธยฐาน (median) เพื่อลดผลจากภาพที่ผิดปกติ → หาค่าสรุปภายในโซน
- **ค่าที่ได้:** ค่าเฉลี่ยของโซน (`lst_mean`) และค่าที่ร้อนที่สุดในระดับ 10% บนสุด (`lst_p90`)

### 3.2 พื้นที่สีเขียว (NDVI) — ไฟล์ `ndvi_2026.csv`
- **ที่มาของข้อมูล:** ภาพดาวเทียม Sentinel-2 ช่วง มี.ค.–พ.ค. 2026 (ละเอียดกว่า Landsat คือ 10 ม.)
- **ขั้นตอน:** ตัดเมฆ เงาเมฆ และพิกเซลที่ใช้ไม่ได้ → คำนวณดัชนีพืชพรรณ NDVI (ยิ่งสูงยิ่งเขียว ค่าอยู่ระหว่าง −1 ถึง 1) → รวมทั้งฤดูด้วยค่ามัธยฐาน
- **ค่าที่ได้:** NDVI เฉลี่ยของโซน (`ndvi_mean`) และสัดส่วนพื้นที่ที่ถือว่าเป็นพื้นที่สีเขียว คือพิกเซลที่ NDVI มากกว่า 0.3 (`green_ratio`)

### 3.3 อาคาร — ไฟล์ `buildings_2026.csv`
- **ที่มาของข้อมูล:** Google Open Buildings v3 (รูปร่างอาคารที่ AI ตรวจจากภาพถ่าย) ใช้เฉพาะอาคารที่ความมั่นใจ ≥ 0.7 ข้อมูลนี้เป็นภาพนิ่ง **ไม่ผูกกับปี** ค่าคอลัมน์ `year` จึงเป็นแค่ป้ายให้เข้ากับไฟล์อื่น
- **ค่าที่ได้:** สัดส่วนพื้นที่หลังคาอาคารต่อพื้นที่โซนเป็นเปอร์เซ็นต์ (`builtup_pct`) และจำนวนอาคารที่มีจุดกึ่งกลางอยู่ในโซน (`building_count`)

### 3.4 คอลัมน์บอกคุณภาพข้อมูล (ใน LST และ NDVI)
- `valid_pixel_ratio` — สัดส่วนพิกเซลในโซนที่มีภาพใช้งานได้จริง (ไม่ถูกเมฆบังตลอด) ยิ่งต่ำยิ่งไม่น่าเชื่อถือ
- `n_scenes` — จำนวนภาพดาวเทียมที่ทับโซนนั้นในช่วงเวลาที่ใช้ ยิ่งน้อยค่าจะยิ่งไม่นิ่ง

## 4. CSV ที่ได้

ทุกไฟล์มีแถวหัวคอลัมน์ และ **key = `community_id` + `buffer_m` + `year` ต้องไม่ซ้ำกัน** ลำดับแถวไม่มีความหมาย

| ไฟล์ | คอลัมน์ | หน่วย / ช่วงค่า |
|---|---|---|
| `lst_2026.csv` | `community_id, buffer_m, year` | รหัสชุมชน, 300 หรือ 500, 2026 |
| | `lst_mean`, `lst_p90` | °C (คาดว่าราว 30–45) |
| | `valid_pixel_ratio` | 0–1 |
| | `n_scenes` | จำนวนเต็ม |
| `ndvi_2026.csv` | `community_id, buffer_m, year` | เหมือนข้างบน |
| | `ndvi_mean` | −1 ถึง 1 |
| | `green_ratio` | 0–1 |
| | `valid_pixel_ratio`, `n_scenes` | เหมือนข้างบน |
| `buildings_2026.csv` | `community_id, buffer_m, year` | เหมือนข้างบน |
| | `builtup_pct` | 0–100 (%) |
| | `building_count` | จำนวนเต็ม (อาคาร) |

- โซนที่ไม่มีพิกเซลใช้ได้เลยอาจได้ช่องว่าง
- ชื่อคอลัมน์ต้องตรงกับ `contracts/lst.yaml`, `contracts/ndvi.yaml`, `contracts/buildings.yaml` ของ repo

| `geojson_to_shapefile.py` | แปลง GeoJSON เป็น Shapefile เพราะ GEE อัปโหลด GeoJSON ไม่ได้ |
