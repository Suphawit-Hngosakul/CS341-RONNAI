# รหัสวัสดุอาคาร `BL_MATL` (building.shp เขตหลักสี่)

**สถานะ: ยังไม่ยืนยันความหมายของรหัส** — ห้ามเขียนลง report ว่ารหัสไหนคือวัสดุอะไร จนกว่าจะมีหลักฐานตามหัวข้อ 3

## 1. สิ่งที่รู้แน่

| ฟิลด์ | ใช้ใน GEE script ราย cell | หมายเหตุ |
|---|---|---|
| `BL_MATL` | แยกสัดส่วนพื้นที่ตามรหัส `0, 1, 2, 3, 8, 9` (`mat0_r` … `mat9_r`) | ค่าเลขรหัส ไม่ใช่ข้อความ |
| `BL_NSTOREY` | จำนวนชั้น (`floors`) | >0 เท่านั้นที่ถูกนับ |
| `BL_AREA` | พื้นที่ฐานอาคาร → ใช้คำนวณ `far` | หน่วยต้องยืนยัน (ตร.ม.?) |

ข้อสังเกตจาก script: รหัสที่ใส่ไว้คือ 0, 1, 2, 3, 8, 9 (ข้าม 4–7) ซึ่งน่าจะเป็นรหัสที่พบจริงในข้อมูลหรือที่เลือกมาจาก data dictionary — ยืนยันกับคนเขียนสคริปต์ว่ามาจากไหน

## 2. ทำไมยังระบุไม่ได้

ค้นเว็บหาเอกสารของฟิลด์ `BL_MATL` แล้วไม่พบ data dictionary สาธารณะเลย รหัสวัสดุแบบนี้ **ไม่มีมาตรฐานกลาง** แต่ละหน่วยงานกำหนดเอง (0 อาจเป็น "ไม่ทราบ" หรือ "ไม้" ก็ได้) การเดาแล้วเอาไปอธิบายสาเหตุความร้อนมีความเสี่ยงสูง จึงเว้นไว้ในตารางด้านล่าง

| รหัส | ความหมาย | แหล่งยืนยัน | จำนวนอาคาร | พื้นที่รวม (ตร.ม.) |
|---|---|---|---|---|
| 0 | ❓ | | | |
| 1 | ❓ | | | |
| 2 | ❓ | | | |
| 3 | ❓ | | | |
| 8 | ❓ | | | |
| 9 | ❓ | | | |

## 3. วิธีหาความหมาย (เรียงจากเร็วไปช้า)

1. **หาไฟล์อธิบายข้อมูลที่มากับ shapefile** — `.xml` (metadata), `.pdf`, `readme`, หรือ Excel ที่แนบมา; เปิด `.dbf` ใน QGIS ดูว่ามีฟิลด์ข้อความคู่กัน เช่น `BL_MATL_DS`, `*_DESC`, `*_NAME`
2. **ถามผู้ให้ข้อมูล** (comment ในโค้ดเดิมก็ระบุว่าต้องยืนยัน) — ขอ data dictionary ของฟิลด์ `BL_MATL` เป็นลายลักษณ์อักษร แล้วแนบที่ช่อง "แหล่งยืนยัน"
3. **ดูการกระจายของรหัสจริง** วางใน GEE:

```js
var bld = ee.FeatureCollection('projects/turnkey-tribute-511903-t6/assets/building');
print('จำนวนอาคารต่อรหัส', bld.aggregate_histogram('BL_MATL'));
print('พื้นที่รวมต่อรหัส', ee.Dictionary(
  bld.reduceColumns({
    reducer: ee.Reducer.sum().group({groupField: 1, groupName: 'code'}),
    selectors: ['BL_AREA', 'BL_MATL']
  }).get('groups')));
print('ค่า BL_MATL ว่าง/null', bld.filter(ee.Filter.notNull(['BL_MATL']).not()).size());
```
   รหัสที่พบน้อยมากหรือเยอะผิดปกติมักบอกใบ้ว่าเป็น "อื่น ๆ/ไม่ทราบ"
4. **สุ่มตรวจสอบด้วยตา** — เลือกรหัสละ 3–5 อาคารที่อยู่คนละที่ เปิด Google Earth / Street View ดูหลังคาและผนัง แล้วจดว่าเห็นอะไร (เป็นหลักฐานเสริม ไม่ใช่แทน data dictionary)

## 4. ข้อควรระวังตอนใช้อธิบายสาเหตุความร้อน

- `BL_MATL` อาจหมายถึง **วัสดุโครงสร้าง** (ไม้ / ก่ออิฐฉาบปูน / คอนกรีตเสริมเหล็ก ฯลฯ) ซึ่งไม่เท่ากับ **วัสดุหลังคา** ที่มีผลต่อ LST จากดาวเทียมโดยตรงที่สุด (ดาวเทียมวัดผิวหลังคา) — ต้องดูว่าฟิลด์นี้หมายถึงส่วนไหน
- ใช้เป็น **สมมติฐาน** ไม่ใช่ข้อสรุป: เช่น "ชุมชนที่สัดส่วนอาคารรหัส X สูง มี LST สูงกว่า" ต้องคุมตัวแปรกวน (NDVI, built-up %, จำนวนชั้น/FAR) ก่อนอ้างว่าวัสดุเป็นสาเหตุ
- ความละเอียด LST คือ 30 ม. (เซ็นเซอร์ความร้อนจริง 100 ม.) ส่วน cell ในสคริปต์คือ 90 ม. ค่าวัสดุต่ออาคารเดี่ยวจึงสะท้อนใน LST ได้จำกัด
- cell ที่ `in_cover = 0` (นอกพื้นที่ที่มีข้อมูลอาคาร) ให้ตัดออกก่อนวิเคราะห์ ไม่เช่นนั้นสัดส่วนวัสดุ = 0 จะเข้าใจผิดว่าไม่มีอาคาร
